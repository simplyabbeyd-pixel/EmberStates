## Operating Rules

- Do not promote compiled indexes, dashboards, filenames, bookmark IDs, or recovered packet summaries into canon by themselves.
- Preserve provenance, uncertainty, duplicate lineage, and unresolved conflicts.
- Keep core EmberStates, EmberStates-related, Hells Branch/runtime, adult/intensity, JanitorAI-adjacent, and external connected material separately classified until explicitly ruled on.
- Hells Branch and runtime material have zero overwrite rights over main Triquel canon unless the Architect explicitly approves a narrow import.
- Treat the ChatGPT project URL as a navigation/work anchor, not readable source proof by itself.
- Treat Chrome `chrome://bookmarks` IDs as local pointers until the original browser profile or exported bookmark HTML gives the destination URL.
- For visual or asset work, separate textual/canon provenance from visual identity. A filename or image-topic match is not exact visual canon.
- Record future work in the Foxglint Contribution Log using the labels UPDATES 📥, CHANGES 🧧, INTEGRATED, MERGED, and [COPIED].
- Keep the existing `VEYRA_QUILL_LIVING_REPOSITORY 🪶🔥` untouched unless the Architect explicitly approves a merge, move, rename, or deletion.

## Preferred Workflow

1. Inventory before editing or merging.
2. Read exact source files or exported text before summarizing claims.
3. Record authority tier and canon status beside each claim.
4. Keep candidate, metadata-only, needs-recovery, quarantined, and approved rows distinct.
5. Ask for or record Architect approval before canon promotion.
6. Read back any registry, sheet, Drive, or repo update after writing.
7. Add or update a running-log entry for each contribution.
